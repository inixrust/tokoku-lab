# L12.1 · Baseline performa

**Hari 5 · berpasangan · 30 menit · slide 115 (pola di slide 106–109)**
**Checkpoint:** `L12-perf` (lihat [mode-perf.md](mode-perf.md))

## Tujuan

Menyusun baseline yang **bisa diulang**: percentile, throughput, CPU, heap, dan connection pool. Semua hasil Hari 5–6
dibandingkan terhadap baseline ini.

## Langkah

1. **Warm-up** 1–2 menit dengan beban ringan ke ketiga endpoint (laju ±50% dari target).
2. **wrk2 `-R` konstan 60 s** ke tiga endpoint (laju awal di bawah; instruktur menetapkan laju final saat dry run):

   ```powershell
   $alice = .\scripts\get-token.ps1 -User alice
   # a. GET product (wajib header versi sejak L5.1)
   .\loadtest\wrk2\run.ps1 -Network tokoku_default -Rate 500 -Url http://product-service:8080/api/products/1 -Header 'API-Version: 1'
   # b. GET order milik alice (page 20)
   .\loadtest\wrk2\run.ps1 -Network tokoku_default -Rate 200 -Url http://order-service:8080/api/orders -Token $alice
   # c. POST order
   .\loadtest\wrk2\run.ps1 -Network tokoku_default -Rate 100 -Url http://order-service:8080/api/orders -Token $alice -Script post-order.lua
   ```

3. **JFR 120 s** selama salah satu uji (mis. b):

   ```powershell
   docker exec tokoku-order-service-1 jcmd 1 JFR.start name=base duration=120s filename=/tmp/base.jfr
   # ...jalankan beban, tunggu 120 s...
   docker cp tokoku-order-service-1:/tmp/base.jfr .\loadtest\results\base.jfr
   ```

   Buka `base.jfr` di JDK Mission Control (Hot Methods, Allocation, Threads).
4. Catat ke tabel, **ulangi 3×**:

| Endpoint | Run | -R | Achieved rps | p50 | p99 | p99.9 | max | Non-2xx | CPU order | Heap | `hikaricp.connections.active` / `pending` |
|---|---|---|---|---|---|---|---|---|---|---|---|
| GET product | 1 | | | | | | | | | | |
| … | | | | | | | | | | | |

- CPU dan heap: dashboard **TokoKu - Golden Signals** (Saturation), atau `docker stats`.
- Hikari: panel HikariCP, atau `curl.exe -s localhost:9082/actuator/prometheus | Select-String hikaricp_connections`.

## Berhasil bila

- [ ] Tabel baseline lengkap, 3 run per endpoint, variasi p99 antar-run < ±15%.
- [ ] Error rate wrk2 = 0 (tidak ada baris `Non-2xx or 3xx responses`).
- [ ] JFR 120 s tersimpan dan bisa dibuka.

## Jebakan umum

- Melaporkan rata-rata (`Latency Avg`) atau memakai load generator closed-loop (`wrk` tanpa `-R`).
- Tanpa header `API-Version` atau token: semua request 400/401, dan "baseline" yang didapat palsu.
- Mengukur tanpa warm-up: p99 dari JIT yang masih dingin (di laptop instruktur: 1000 rps tanpa warm-up → p99 220 ms).
- Token kedaluwarsa (30 menit) di tengah uji: ambil ulang sebelum setiap sesi.
