# L3.1 · product-service di Boot 4.1

**Hari 1 · individu · 30 menit · slide 27**
**Checkpoint:** `L3.1-start` → `L3.1-solution`
**Infra:** `docker compose -f infra/compose.yaml --profile db up -d`

## Tujuan

Membuat product-service dari start.spring.io (Boot 4.1.x, Java 21) dan membuktikan urutan override configuration.

## Langkah

### 1. Generate proyek

Buka <https://start.spring.io> dan isi:

| Isian | Nilai |
|---|---|
| Project / Language | Maven / Java |
| Spring Boot | 4.1.2 |
| Group / Artifact | `com.tokoku` / `product-service` |
| Package name | `com.tokoku.product` |
| Java | 21 |
| Dependencies | Spring Web, Spring Data JPA, Flyway Migration, Spring Boot Actuator, Validation, PostgreSQL Driver |

Ekstrak ZIP ke folder `tokoku-lab/product-service/`, lalu hapus file yang sudah disediakan di root repo:
`mvnw`, `mvnw.cmd`, `.mvn/`, `.gitignore`, `.gitattributes`, `HELP.md`.

### 2. Sambungkan ke parent TokoKu

Di `product-service/pom.xml`, ganti blok `<parent>` dan hapus `<groupId>` milik proyek (diwarisi dari parent):

```xml
<parent>
    <groupId>com.tokoku</groupId>
    <artifactId>tokoku-parent</artifactId>
    <version>1.0.0-SNAPSHOT</version>
    <relativePath>../pom.xml</relativePath>
</parent>
<artifactId>product-service</artifactId>
```

Ubah juga `<version>` menjadi `1.0.0-SNAPSHOT` (atau hapus agar ikut parent), dan hapus `<properties><java.version>`
(sudah ada di parent). Di `pom.xml` root, tambahkan `<module>product-service</module>`.

### 3. Amati starter Boot 4

Bandingkan dependency yang dihasilkan dengan tutorial Boot 3 yang biasa Anda temui:

- Nama starter web sekarang apa? Starter Flyway?
- Untuk setiap starter, starter apa yang ikut ditambahkan dengan scope `test`?

### 4. Configuration aplikasi

Ganti `src/main/resources/application.properties` dengan `application.yml`:

```yaml
spring:
  application:
    name: product-service
  datasource:
    url: jdbc:postgresql://localhost:5432/tokoku
    username: product_user
    password: product_pw
  jpa:
    open-in-view: false

server:
  port: 8081

management:
  server:
    port: 9081
  endpoints:
    web:
      exposure:
        include: health, info, env, configprops

tokoku:
  inventory:
    base-url: http://localhost:8083
    read-timeout: 2s
```

User `product_user` hanya bisa mengakses schema `product` (lihat `infra/postgres/init.sql`).

### 5. Record `InventoryProps`

Buat record di package `com.tokoku.product.infrastructure.config` (pola slide 24):

- `@Validated` + `@ConfigurationProperties("tokoku.inventory")`
- `baseUrl` wajib (`@NotBlank`), `readTimeout` wajib (`@NotNull Duration`),
  `maxAttempts` dengan default 3 dan minimal 1.

Aktifkan dengan `@ConfigurationPropertiesScan` di class aplikasi, lalu **cetak nilainya saat startup**
(mis. lewat bean `ApplicationRunner`).

### 6. Buktikan urutan override

Jalankan `ProductServiceApplication` tiga kali dan catat port yang dipakai (lihat log `Tomcat started on port ...`):

| Run | Program argument | Environment variable | Port |
|---|---|---|---|
| a | — | — | |
| b | `--server.port=7070` | `SERVER_PORT=9090` | |
| c | — | `SERVER_PORT=9090` | |

Lalu coba juga `TOKOKU_INVENTORY_READTIMEOUT=3s` dan lihat nilai yang tercetak.

**Cara memberi argument dan env var:**

- **IntelliJ IDEA:** Run > Edit Configurations > `ProductServiceApplication` > *Program arguments* dan *Environment variables*.
- **VS Code:** di `.vscode/launch.json`, isi `"args"` dan `"env"` pada konfigurasi product-service.
- **Terminal:** `$env:SERVER_PORT=9090; .\mvnw.cmd -pl product-service spring-boot:run "-Dspring-boot.run.arguments=--server.port=7070"`
  (hapus lagi dengan `Remove-Item Env:SERVER_PORT`).

### 7. Fail fast

Hapus baris `base-url` dari `application.yml` lalu jalankan ulang. Apa yang terjadi, dan di mana pesan errornya?
Kembalikan baris tersebut setelahnya.

## Berhasil bila

- [ ] Aplikasi jalan di **7070** pada run (b), dan Anda bisa menjelaskan mengapa argument mengalahkan env var.
- [ ] Nilai `InventoryProps` tercetak saat startup (termasuk `maxAttempts=3` dari default).
- [ ] Tanpa `base-url`, aplikasi **gagal start** dengan pesan yang menyebut property tersebut.
- [ ] `.\mvnw.cmd -pl product-service verify` sukses (infra profil `db` harus menyala).

## Jebakan umum

- Menyalin dependency dari tutorial Boot 3 (`spring-boot-starter-web`, `flyway-core` saja). Di Boot 4,
  `flyway-core` tanpa `spring-boot-starter-flyway` membuat migrasi **diam-diam tidak jalan**.
- Lupa `@ConfigurationPropertiesScan`: record tidak terdaftar sebagai bean, sehingga injeksi gagal.
- Lupa menghapus `SERVER_PORT` dari environment terminal, lalu bingung di lab berikutnya.
