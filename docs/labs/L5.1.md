# L5.1 · API product berversi + RFC 9457

**Hari 2 · berpasangan · 30 menit · slide 42**
**Checkpoint:** `L5.1-start` → `L5.1-solution`
**Infra:** `docker compose -f infra/compose.yaml --profile db up -d`

## Tujuan

Membangun endpoint product v1/v2 berbasis header `API-Version`, dengan error response RFC 9457 yang konsisten.

## Yang sudah disediakan

- Domain `Product`, `ProductService`, repository JPA, dan Flyway (`V1__create_product.sql`, 20 product contoh).
- `ProductController` tanpa versi: list (`PagedModel`), get by id, search, create.
- Exception domain `ProductNotFoundException` (404) dan `DuplicateSkuException` (409).
- Koleksi Bruno `bruno/tokoku` (folder `product`) berisi 9 request **beserta test**. Pilih environment `local`.

Jalankan product-service lalu jalankan koleksi Bruno. Catat request mana yang gagal sebelum Anda mulai.

## Langkah

### 1. Aktifkan API versioning

Di `application.yml`, versi dibaca dari header `API-Version`, dan hanya `1` dan `2` yang diterima (slide 33).
Tambahkan atribut `version` pada mapping:

- `GET /api/products/{id}` punya dua handler: `version = "1"` mengembalikan `ProductV1`,
  `version = "2"` mengembalikan `ProductV2` (DTO record baru, mis. menambahkan `sku` dan
  harga sebagai objek `{ "amount": ..., "currency": "IDR" }`).
- Handler lain (list, search, create) belum berubah: pakai `version = "1+"`, artinya berlaku untuk versi 1
  dan sesudahnya. Bandingkan dengan `version = "1"`: apa yang terjadi bila client v2 memanggil list?

### 2. `ApiExceptionHandler`

Buat `@RestControllerAdvice` yang meng-extend `ResponseEntityExceptionHandler` (slide 38–39):

- `ProductNotFoundException` → 404 `ProblemDetail` dengan `type`, `title`, `errorCode`, `productId`.
- `DuplicateSkuException` → 409 dengan `errorCode` dan `sku`.
- Fallback `Exception` → 500 generik **tanpa** detail internal; detail hanya di log.

### 3. Uji dua jalur validation

Kirim `POST /api/products` dengan body invalid dan `GET /api/products/search?q=ko`.
Keduanya harus 400 `application/problem+json`. Bila salah satu masih 500, cari tahu exception apa yang
dilempar (lihat log) dan mengapa (slide 36).

### 4. Jalankan ulang koleksi Bruno

Semua test di folder `product` harus hijau.

Tanpa Bruno, contoh dengan `curl.exe`:

```powershell
curl.exe -i -H "API-Version: 1" localhost:8081/api/products/999
curl.exe -i -H "API-Version: 1" "localhost:8081/api/products/search?q=ko"
curl.exe -i -H "API-Version: 1" -H "Content-Type: application/json" -d '{\"sku\":\"\",\"name\":\"Kopi\",\"price\":-1}' localhost:8081/api/products
curl.exe -i localhost:8081/api/products/1
```

## Berhasil bila

- [ ] Empat skenario error (404, 409, body invalid, `q` pendek) mengembalikan `application/problem+json`
      dengan field `status` = status HTTP.
- [ ] Request tanpa header versi dan dengan `API-Version: 3` menghasilkan 400.
- [ ] `API-Version: 1` dan `2` mengembalikan bentuk JSON yang berbeda untuk product yang sama.
- [ ] Response 500 tidak membocorkan nama class, stack trace, atau SQL.

## Jebakan umum

- Hanya menangani `MethodArgumentNotValidException`; `HandlerMethodValidationException` (constraint di parameter)
  terlewat.
- Menyisakan `@Validated` di class controller: constraint parameter divalidasi oleh AOP dan melempar
  `ConstraintViolationException` (jadi 500), bukan jalur validation bawaan Spring MVC.

> **Mulai lab ini**, setiap call ke product-service (Bruno, wrk2, test) wajib membawa header `API-Version`.
