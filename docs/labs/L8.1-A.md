# L8.1-A · order → inventory via `@HttpExchange`

**Hari 2 · berpasangan · 30 menit · slide 54, slide 50–51**
**Checkpoint:** `L8.1A-start` → `L8.1A-solution`
**Infra:** `docker compose -f infra/compose.yaml --profile db up -d`

## Tujuan

order-service memanggil inventory-service lewat HTTP Service Client (`@HttpExchange`) dengan connect timeout dan
read timeout, lalu membuktikan perilakunya saat inventory **mati** dan saat inventory **lambat**.

## Yang sudah disediakan

- **inventory-service** siap jalan (port 8083 / 9083):
  - `GET /api/inventory/{productId}` → `{"productId": 1, "available": 100}`. Product 19 hanya 2 unit, product 20 habis.
  - Mode lambat: property `inventory.simulated-delay`, atau saat runtime:
    `curl.exe -X PUT "localhost:8083/api/admin/simulated-delay?value=8s"` (kembalikan dengan `value=0s`).
- order-service:
  - Port `StockCheck`; `PlaceOrderService` mengecek stok setiap item **sebelum** transaction, lalu
    `INSUFFICIENT` → 409.
  - `InventoryProps` (`tokoku.inventory.base-url`).
  - Adapter `InventoryStockAdapter` masih **stub** (selalu `AVAILABLE`).
- Bruno: folder `inventory` dan `order/place order (alice)`.

## Langkah

### 1. Client deklaratif

1. Tambahkan `spring-boot-starter-restclient` (dan pasangan `-test`) ke `order-service/pom.xml`.
2. Di `infrastructure/adapters/out/http`, buat interface `InventoryClient`:
   `@HttpExchange("/api/inventory")` dengan method `@GetExchange("/{productId}")` yang mengembalikan record
   `StockResponse(long productId, int available)`.
3. Di `infrastructure/config`, buat `HttpClientsConfig` (slide 50): `@ImportHttpServices(group = "inventory", ...)`
   dan bean `RestClientHttpServiceGroupConfigurer` yang mengisi `baseUrl` dari `InventoryProps`.
4. Ganti stub `InventoryStockAdapter` agar memakai `InventoryClient`.

Uji: `POST /api/orders` untuk product 20 harus 409, product 1 harus 201.

### 2. Timeout global (slide 51)

```yaml
spring:
  http:
    clients:
      connect-timeout: 2s
      read-timeout: 5s
```

### 3. Uji kegagalan

Ukur durasi `POST /api/orders` (Bruno menampilkan waktu respons; di PowerShell:
`Measure-Command { curl.exe -s -o NUL -X POST ... }`).

| Kasus | Cara | Durasi | Status / error di log |
|---|---|---|---|
| a. Inventory **mati** | hentikan inventory-service | | |
| b. Inventory **lambat 8 s**, dengan timeout | `simulated-delay=8s` | | |
| c. Inventory lambat 8 s, **tanpa** read timeout | hapus `read-timeout`, restart order-service | | |

**Opsional:** arahkan `tokoku.inventory.base-url` ke IP yang tidak bisa dirutekan (`http://10.255.255.1:8083`).

## Jebakan umum

- Membuat `RestClient.create()` sendiri: property `spring.http.clients.*` hanya berlaku untuk builder yang
  di-inject Spring, jadi client buatan sendiri **tanpa timeout** dan request menggantung saat downstream lambat.
- Mengira inventory yang mati menunggu connect timeout. Port tertutup di `localhost` langsung ditolak
  (*connection refused*).
