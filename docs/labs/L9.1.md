# L9.1 · Eureka (pekerjaan rumah opsional)

lab berikutnya **tidak** bergantung pada lab ini)
**Infra:** `docker compose -f infra/compose.yaml --profile db --profile kafka --profile obs up -d`

## Tujuan

Merasakan client-side discovery: order-service memanggil inventory **lewat nama service**, Spring Cloud
LoadBalancer membagi request ke dua instance, dan sistem tetap jalan saat satu instance mati.

## Yang sudah disediakan

- Modul `discovery-server` (Eureka, port 8761). Dashboard: <http://localhost:8761>.
- Untuk lab: self-preservation dimatikan dan eviction dipercepat (`discovery-server/src/main/resources/application.yml`).

## Langkah

1. Jalankan `discovery-server`.
2. Tambahkan `spring-cloud-starter-netflix-eureka-client` ke **inventory-service** dan **order-service**, lalu:

   ```yaml
   eureka:
     client:
       service-url:
         defaultZone: http://localhost:8761/eureka
       registry-fetch-interval-seconds: 5
     instance:
       instance-id: ${spring.application.name}:${server.port}
       lease-renewal-interval-in-seconds: 5
       lease-expiration-duration-in-seconds: 10
   ```

3. Di order-service, ganti `tokoku.inventory.base-url` menjadi `http://inventory-service` (nama service, bukan
   host:port). Spring Cloud LoadBalancer otomatis dipasang ke grup HTTP service `inventory`.
4. Jalankan dua instance inventory: port **8083** (biasa) dan **8093**
   (`--server.port=8093 --management.server.port=9093`).
5. Buat ±20 order (product 2), lalu cek pembagian request:
   - Grafana Explore, Prometheus:
     `sum by (instance) (http_server_requests_milliseconds_count{service_name="inventory-service",uri="/api/inventory/{productId}"})`
   - Agar label `instance` berbeda per instance, tambahkan di inventory:
     `management.opentelemetry.resource-attributes.service.instance.id: ${HOSTNAME:${COMPUTERNAME:local}}:${server.port}`
6. **Matikan** instance 8093 (tombol Stop di IDE), lalu langsung kirim order berulang setiap 2 detik selama 20 detik.

## Berhasil bila

- [ ] Dashboard Eureka menampilkan 2 instance `INVENTORY-SERVICE`.
- [ ] Request terbagi ke dua instance (round-robin).
- [ ] Setelah satu instance mati, sebagian request gagal (503) selama beberapa detik, lalu **semua** kembali 201.
      Catat berapa lama jendela gagalnya, dan jelaskan dari mana angka itu berasal (lease expiration, eviction,
      registry fetch, cache LoadBalancer).
