# L11.1 · Resource server + uji BOLA

**Hari 4 · berpasangan · 35 menit · slide 95 (pola di slide 87–91)**
**Checkpoint:** `L11.1-start` → `L11.1-solution`
**Infra:** `docker compose -f infra/compose.yaml --profile db --profile kafka --profile obs --profile security --profile chaos up -d`

## Tujuan

Mengamankan order-service sebagai resource server JWT (Keycloak), lalu menemukan dan menutup celah **BOLA**
(OWASP API1).

## Yang sudah disediakan

- **Keycloak** <http://localhost:8180> (admin/admin), realm `tokoku` diimpor otomatis dari
  `infra/keycloak/realm-tokoku.json`:

  | Item | Isi |
  |---|---|
  | Client `tokoku-web` | public, authorization code + **PKCE**, scope default `orders.read orders.write`, token 30 menit (khusus lab) |
  | Client `tokoku-loadtest` | confidential, **client credentials**, scope `payments.write` (otomasi/load test) |
  | Client scope `orders.read`, `orders.write`, `payments.write` | masing-masing punya **audience mapper** `order-service` |
  | User | `alice`/`alice` dan `bob`/`bob`, dengan ID tetap = `customer_id` di data seed |

- `scripts/get-token.ps1`:

  ```powershell
  $alice = .\scripts\get-token.ps1 -User alice -Decode   # PKCE tanpa browser, tampilkan klaim
  $bob   = .\scripts\get-token.ps1 -User bob
  $svc   = .\scripts\get-token.ps1 -ClientCredentials
  ```

  Bruno: isi variabel secret `aliceToken`, `bobToken`, `serviceToken` di environment `local`
  (`.\scripts\get-token.ps1 -User alice -Copy` menyalin token ke clipboard). Bruno juga bisa mengambil token
  sendiri lewat OAuth2 authorization code + PKCE (client `tokoku-web`).

## Langkah

### 1. Walk-through Keycloak (instruktur)

Di admin console: realm `tokoku` → Client scopes → `orders.read` → Mappers → **audience order-service**.
Tanpa mapper ini, klaim `aud` tidak berisi `order-service` dan validasi audience menolak semua token.

### 2. Resource server

1. Tambahkan `spring-boot-starter-security-oauth2-resource-server` ke order-service.
2. Konfigurasi (slide 89):

   ```yaml
   spring:
     security:
       oauth2:
         resourceserver:
           jwt:
             issuer-uri: http://localhost:8180/realms/tokoku
             audiences: order-service
             jws-algorithms: RS256
   ```

3. Tulis `SecurityFilterChain` dengan Lambda DSL (slide 88):
   - `/actuator/health/**` publik;
   - `GET /api/orders/**` → `SCOPE_orders.read`; `POST /api/orders` → `SCOPE_orders.write`;
   - `POST /api/payments` → `SCOPE_payments.write`;
   - `anyRequest().authenticated()`, stateless, CSRF off (bearer token, tanpa cookie).
4. `customerId` order baru diambil dari token (`jwt.getSubject()`), **bukan** dari body request.

### 3. Uji BOLA

Dengan token alice: `GET /api/orders/1` (order 1 milik **bob**; Bruno `order/BOLA ...`). Catat hasilnya.

### 4. Perbaikan

Batasi **query** di application layer dengan pemilik (slide 91):
`GetOrderUseCase.get(orderId, customerId)` → `findByIdAndCustomerId(...)`; bukan milik pemanggil → **404**
(keberadaan data tidak bocor). Lakukan hal yang sama untuk list: alice hanya melihat order miliknya.

Variant: `@PreAuthorize` + `@EnableMethodSecurity` dengan ownership check. Bandingkan: di mana pengecekannya terjadi,
dan apa yang terjadi pada list?

## Berhasil bila

| Request | Hasil |
|---|---|
| Tanpa token | **401** |
| Token `tokoku-loadtest` (hanya `payments.write`) ke `GET /api/orders/{id}` | **403** |
| Alice → order milik bob, **sebelum** perbaikan | 200 (bocor) |
| Alice → order milik bob, **sesudah** perbaikan | **404** |
| Alice → list order | hanya order alice |
| Token `tokoku-loadtest` ke `POST /api/payments` | 201 |

## Jebakan umum

- Menganggap scope/role `orders.read` cukup untuk membaca order **mana pun**.
- Mengambil `customerId` dari body/path request, bukan dari token.
- `iss` di token harus sama persis dengan `issuer-uri`: `http://localhost:8180/realms/tokoku`
  (bukan `127.0.0.1`, bukan `keycloak:8080`).
- Lupa audience mapper di Keycloak, atau lupa `audiences` di Spring: token untuk API lain ikut diterima (D11.3).

> **Mulai lab ini**, semua call ke order-service butuh token: `/api/orders` dengan token alice,
> `/api/payments` dengan token `tokoku-loadtest`. Token berumur 30 menit; ambil ulang bila 401.
