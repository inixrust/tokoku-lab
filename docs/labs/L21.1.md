## Tujuan

Membangun image produksi, men-deploy product-service ke Kubernetes dengan probe dan graceful shutdown yang benar,
lalu membuktikan: **DB mati → readiness turun, liveness tetap, 0 restart**.

> Slide 158–159 memakai nama order-service; polanya sama. Lab memakai **product-service** karena dependensinya hanya
> PostgreSQL, sehingga skenario "DB mati" bersih. Kelas memakai Kubernetes Docker Desktop (bukan kind).

## Langkah

### 1. Build image

```powershell
.\mvnw.cmd -pl product-service package -DskipTests
docker build -t product-service:1.0 product-service
docker image inspect product-service:1.0 --format "user={{.Config.User}} size={{.Size}}"
```

Pakai tag versi (`1.0`), bukan `latest`, + `imagePullPolicy: IfNotPresent`: image lokal langsung terlihat oleh cluster.

### 2. Deploy dengan probe dan graceful shutdown (slide 158)

1. `kubectl config use-context docker-desktop`
2. Di `deployment.yaml`:
   - `terminationGracePeriodSeconds: 45` (> preStop 10 s + timeout shutdown Spring 30 s);
   - `lifecycle.preStop.sleep.seconds: 10`;
   - `livenessProbe` → `/actuator/health/liveness`, `readinessProbe` → `/actuator/health/readiness`, keduanya di port
     **management** (8081).
3. Di `config.yaml`: grup readiness memasukkan DB, liveness **tidak**:
   `MANAGEMENT_ENDPOINT_HEALTH_GROUP_READINESS_INCLUDE: readinessState,db`.
   Secara default grup readiness Boot hanya berisi `readinessState`, sehingga DB mati **tidak** menurunkan readiness.
4. `kubectl apply -f k8s/` lalu `kubectl rollout status deploy/product-service`.

### 3. Matikan DB

```powershell
kubectl get pods -l app=product-service -w        # jendela terpisah
docker compose -f infra/compose.yaml stop postgres
# tunggu ±30 s, amati READY dan RESTARTS
docker compose -f infra/compose.yaml start postgres
```

### 4. Review checklist slide 160

Bahas checklist kesiapan produksi untuk product-service: mana yang sudah, mana yang belum. (Langkah 4 di slide 162.)

## Berhasil bila

- [ ] Image berjalan sebagai non-root (`user=10001`).
- [ ] Saat DB mati: `kubectl get pods` menunjukkan **`READY 0/1`** tanpa kenaikan **`RESTARTS`**.
- [ ] Setelah `docker compose start postgres`: kembali `1/1`.

## Jebakan umum

- **Liveness probe yang memeriksa database**: DB mati → semua pod di-restart bersamaan (D21.1), padahal restart tidak
  memperbaiki DB.
- Tanpa readiness probe: pod dianggap siap sebelum Spring selesai start, sehingga request pertama gagal.
- `terminationGracePeriodSeconds` lebih kecil dari preStop + shutdown Spring: request yang sedang berjalan terpotong
  SIGKILL.
- Pod crash dengan `FATAL: remaining connection slots are reserved ...`: total connection (pool × instance, termasuk
  container mode perf yang masih jalan) melewati `max_connections` PostgreSQL (100). Hentikan profil `apps` dulu
  (`docker compose ... --profile apps stop`) atau hitung ulang (slide 132).
- Docker Desktop dengan provisioner **kind** (multi-node) tidak berbagi image store: `ErrImageNeverPull` /
  `ImagePullBackOff`. Pakai mode kubeadm (dicek `verify-env.ps1`).
