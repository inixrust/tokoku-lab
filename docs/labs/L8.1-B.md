# L8.1-B · notification-service + metric

**Hari 3 · berpasangan · 25 menit · slide 69, slide 68**
**Checkpoint:** `L8.1B-start` → `L8.1B-solution`
**Infra:** `docker compose -f infra/compose.yaml --profile db --profile kafka --profile obs up -d`

## Tujuan

notification-service mengonsumsi `OrderPlaced` (yang dikirim lewat outbox dari L7.1), lalu metric HTTP client
order → inventory dibuka lewat Actuator dan Grafana.

## Yang sudah disediakan

- `notification-service` (port 8084 / 9084): aplikasi kosong + kontrak event `OrderPlaced`.
- Semua service mengekspor metric dan trace lewat **OTLP** ke `grafana/otel-lgtm` (dependency
  `spring-boot-starter-opentelemetry` dan blok `management.otlp`/`management.opentelemetry` di `application.yml`).
  Ini scaffolding; cara kerjanya dibahas di Hari 6 (Modul 20 lanjutan).
- Grafana: <http://localhost:3000> (admin/admin), folder **TokoKu → TokoKu - Golden Signals**.

## Langkah

### 1. Listener notification (slide 69, langkah 1–2)

Di `notification-service`, buat `@KafkaListener(topics = "orders")` yang:

- hanya memproses record dengan header `eventType = OrderPlaced`;
- membaca payload JSON menjadi `OrderPlaced` (bean `JsonMapper`);
- mencetak log, mis. `Kirim email ke customer ... : order ... diterima (N item)`.

Consumer group-nya `notification-service` (sudah diatur), berbeda dari `inventory-service`, sehingga **kedua**
service menerima setiap event.

### 2. Endpoint Prometheus (slide 68; slide 69 langkah 3)

Di **order-service**:

1. Tambahkan dependency `io.micrometer:micrometer-registry-prometheus` (scope `runtime`).
2. Ekspos endpoint seperlunya:

```yaml
management:
  endpoints:
    web:
      exposure:
        include: health, info, prometheus
  endpoint:
    health:
      show-details: when-authorized
```

3. Buka <http://localhost:9082/actuator/prometheus> (**management port**, bukan 8082) dan cari
   `http_client_requests`. Tag apa saja yang ada? Mana `uri` dan `status`?

### 3. Lihat di Grafana

Buat beberapa order (Bruno `order/place order (alice)`), lalu buka dashboard **TokoKu - Golden Signals**.
Panel *HTTP client (downstream)* menunjukkan panggilan order → inventory.

## Berhasil bila

- [ ] Log notification muncul untuk **setiap** order baru.
- [ ] `http_client_requests_seconds_count{...uri="/api/inventory/{productId}"...}` terlihat di `/actuator/prometheus`.
- [ ] Panel HTTP client dan latency order-service di Grafana terisi.

## Jebakan umum

- Mengekspos semua endpoint (`include: "*"`): `heapdump` dan `env` ikut terbuka.
- Membuka `/actuator/prometheus` di port aplikasi (8082) lalu mengira endpoint tidak aktif.
- Memakai consumer group yang sama dengan inventory: event dibagi, bukan diterima keduanya.
