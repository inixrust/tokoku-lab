# L12.2 · JMeter open model

**Hari 5 · berpasangan · 25 menit · slide 116 (pola di slide 111–113)**
**Checkpoint:** `L12-perf` (lihat [mode-perf.md](mode-perf.md))
**Jawaban:** tag `L12.2-solution` (`payments.jmx` lengkap), dirilis setelah pembahasan

## Tujuan

Melengkapi test plan JMeter untuk `POST /api/payments` dengan **open model**, menjalankannya di CLI, lalu
membandingkan hasilnya dengan metric server-side dan wrk2.

## Yang sudah disediakan

`loadtest/jmeter/payments.jmx` (struktur slide 112), hampir jadi:

- setUp Thread Group: ambil token **client credentials** (`tokoku-loadtest`, scope `payments.write`) sekali,
  lalu dibagikan ke thread lain lewat property `accessToken`.
- Open Model Thread Group + CSV `loadtest/data/customers.csv` (sintetis) + header `Authorization` dan
  `Idempotency-Key: ${__UUID()}` (unik per request).
- `user.properties`: percentile p90/p99/p99.9 di HTML report. `run.ps1`: eksekusi CLI.

## Langkah

1. Buka di GUI (hanya untuk desain): `jmeter.bat -t loadtest\jmeter\payments.jmx`.
2. Lengkapi **schedule** Open Model Thread Group. Versi kelas (property `-J`): ramp-up 30 s, steady 3 menit,
   ramp-down 30 s:

   ```
   rate(0/s) random_arrivals(${__P(rampup,30)} s) rate(${__P(rps,200)}/s)
   random_arrivals(${__P(steady,180)} s)
   rate(${__P(rps,200)}/s) random_arrivals(${__P(rampdown,30)} s) rate(0/s)
   ```

   Schedule di slide 112 (2 + 10 + 1 menit) adalah durasi uji sungguhan; tidak muat dalam 25 menit.
3. Tambahkan **Response Assertion** di sampler `POST /api/payments`: response code = 201.
4. Simpan, tutup GUI, jalankan di **CLI**:

   ```powershell
   .\loadtest\jmeter\run.ps1 -Rps 200            # JMeter lokal
   .\loadtest\jmeter\run.ps1 -Rps 200 -Docker    # tanpa JMeter lokal
   ```

5. Buka `loadtest\results\payments-<waktu>\report\index.html`.

## Berhasil bila

- [ ] Dashboard HTML terbit.
- [ ] **Achieved throughput ≈ target** (±5%) pada fase steady; error rate ≈ 0.
- [ ] p99 JMeter dibandingkan dengan p99 `http.server.requests` (Grafana, `POST /api/payments`) dan dengan wrk2;
      Anda bisa menjelaskan selisihnya (jaringan, kalibrasi, koreksi coordinated omission, granularitas histogram).

## Jebakan umum

- Menjalankan load test dari **GUI** dengan View Results Tree aktif: JMeter sendiri yang menjadi bottleneck.
- Thread Group biasa (closed model): laju turun saat server melambat, dan latency terburuk tersembunyi.
- Idempotency-Key yang sama untuk semua request: semua kecuali yang pertama menjadi replay (bukan beban nyata).
