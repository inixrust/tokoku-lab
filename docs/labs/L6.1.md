# L6.1 · Persistence order-service

**Hari 2 · berpasangan · 35 menit · slide 48**
**Checkpoint:** `L6.1-start` → `L6.1-solution`
**Infra:** `docker compose -f infra/compose.yaml --profile db up -d`

## Tujuan

Memetakan Order–OrderItem dengan LAZY eksplisit, SEQUENCE, dan Flyway, lalu menghitung query per request.

## Yang sudah disediakan

- order-service hexagonal (slide 25): domain `Order`/`OrderLine`, use case `PlaceOrderUseCase`/`GetOrderUseCase`,
  `OrderController`, `ApiExceptionHandler` (pola L5.1).
- Adapter persistence **kosong**: `infrastructure/adapters/out/persistence/JpaOrderStore` melempar
  `UnsupportedOperationException`.
- Seed `db/migration/V2__seed_orders.sql`: 50 order × 3 item milik alice dan bob.
- Bruno: folder `order`.

## Langkah

### 1. Dependency dan Flyway

Di `order-service/pom.xml`, ganti dependency sementara `spring-boot-data-commons` dan `spring-tx` dengan:
`spring-boot-starter-data-jpa`, `spring-boot-starter-flyway`, `flyway-database-postgresql`, `postgresql` (runtime),
ditambah pasangan `-test` untuk kedua starter.

Tambahkan datasource ke `application.yml`:

```yaml
spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/tokoku
    username: order_user
    password: order_pw
```

Tulis `src/main/resources/db/migration/V1__init.sql`. Nama tabel dan kolom harus cocok dengan seed `V2`:

| Tabel | Kolom |
|---|---|
| `orders` | `id bigint PK`, `customer_id varchar(64)`, `status varchar(20)`, `created_at timestamptz`, `version bigint` |
| `order_items` | `id bigint PK`, `order_id bigint FK → orders`, `product_id bigint`, `quantity int` |

Buat juga **sequence** untuk kedua tabel. Seed memakai ID 1–150, jadi mulai sequence dari 1001.

### 2. Entity

Di package `infrastructure.adapters.out.persistence`:

- `OrderEntity` (`@Table(name = "orders")`): ID SEQUENCE, `@Version`, `@OneToMany(mappedBy = "order", cascade = ALL)`.
- `OrderItemEntity`: ID SEQUENCE, `@ManyToOne(fetch = FetchType.LAZY)` ke order. `product_id` hanya ID, bukan relationship.
- Repository Spring Data + mapper entity ↔ domain, lalu implementasikan `JpaOrderStore`.

Matikan OSIV: `spring.jpa.open-in-view: false`.

### 3. Statistik Hibernate

```yaml
spring:
  jpa:
    properties:
      hibernate.generate_statistics: true

logging:
  level:
    org.hibernate.session.metrics: debug
```

Di Hibernate 7, ringkasan per session ditulis logger `org.hibernate.session.metrics` pada level **DEBUG**,
jadi `generate_statistics` saja tidak menampilkan apa pun. Cari baris `... executing N JDBC statements`.

## Jebakan umum

- Menambal `LazyInitializationException` dengan `FetchType.EAGER` atau menyalakan OSIV lagi. Perbaiki fetch plan,
  atau (untuk lab ini) pastikan mapping ke domain terjadi **di dalam** transaction.
- **Sequence tidak cocok.** Hibernate memakai `allocationSize` 50 secara default, jadi sequence harus
  `INCREMENT BY 50`, dan namanya harus sama dengan yang dicari Hibernate. Paling aman: tulis
  `@SequenceGenerator(name = ..., sequenceName = ..., allocationSize = 50)` secara eksplisit.
